# Проверка админки и API Chill Hub · 16 ноября 2026

Область проверки включает 55 исходных файлов Go в 16 пакетах и 33 файла JS, CSS и HTML админки. Маршруты сверены с запросами панели и форматами ответов лаунчера. Проверка прошла в три этапа с исправлениями перед переходом к следующему. Ручная проверка шла по сценариям, перечисленным ниже. Все пакеты и веб-тесты вошли в автоматические прогоны.

## 1. Границы доступа и корректность ответов

- Запрос к галерее с закодированным переходом к родительскому каталогу мог открыть файл сборки. Вложенный каталог можно было получить списком. Обработчик проверяет путь после декодирования, открывает файл внутри каталога конкретной галереи и отдаёт только обычные файлы.
- Загрузки картинок доверяли имени и заявленному типу. Ветка без FFmpeg могла сохранить произвольные байты с расширением HTML. Загрузка обложки тоже принимала произвольные байты. Тип определяется по содержимому, FFmpeg получает явный входной формат, а переименование файла сохраняет расширение.
- Вход мог использовать поля из частично разобранного тела или строки запроса. Некорректное, лишнее и слишком большое содержимое теперь вызывает отказ без выдачи сессии.
- Публичный API проверяет идентификаторы и версии по тем же правилам, что запись реестра и публикация сборок. Служебные имена отделены от идентификаторов игр и имён сборок. Запись новостей с явно неверным значением флага публикации в выдачу не попадает.
- Запись с разрешённого origin может передать заголовки CSRF и проверки ревизии реестра. Короткие подписи и URL загрузки остаются в теле запроса.

## 2. Параллельные операции и восстановление

- Загрузка архива, публикация сборки, активация, удаление, очистка версий и дозапись манифеста используют один замок на каталог манифестов. После захвата замка проверяются результаты, от которых зависит запись, в том числе активная версия.
- Чанки одного архива можно писать параллельно. Повтор уже принятого чанка сохраняет прежние байты. Завершение, распаковка и удаление не идут одновременно с записью чанков этого архива. Ручная очистка и фоновая уборка пропускают занятый архив.
- Повтор завершения загрузки возвращает ту же контрольную сумму. После несовпадения суммы пометки о получении сбрасываются, в том числе когда ZIP уже переименован, а состояние готовности ещё не записано. Повтор распаковки после успеха возвращает результат без повторной публикации.
- Запись состава модпака готовится в том же временном каталоге, что его файлы. При публикации они переезжают вместе, при откате возвращаются вместе. Чтение поддерживает старое расположение записи. Тест перекрывает две публикации одной версии и сверяет итоговый состав и отпечаток файлов.
- Компакция обращений останавливается при ошибке чтения журнала. Для записи используется общий механизм атомарной замены.

## 3. Повторная сверка сценариев админки

- Чистка версий отправляет серверу именно тот список, который оператор подтвердил. Сервер сверяет список под замком и отклоняет устаревшее подтверждение. Панель показывает число действительно удалённых версий и сообщает о частичном отказе.
- Запись реестра привязана к его прочитанной ревизии. Панель блокирует сохранение, если чтение не удалось. Названия со знаками кавычек проходят через сериализацию аргументов действий.
- Параллельные ответы 401 используют одно продление сессии. Чанковая загрузка через XHR тоже проверяет сессию перед повтором. Ошибка одного обработчика чанка освобождает очередь и учитывается как неудачная загрузка.

## Проверки

- Go 1.26.11 в Ubuntu через WSL. Все 16 пакетов прошли `go vet ./...` и `go test -race -timeout 120s ./...`. `golangci-lint run` версии 2.15.0 завершился без замечаний. На Windows все 16 пакетов прошли `go vet ./...` и `go test -timeout 120s ./...` с Git Bash для проверки уведомлений.
- Node с зависимостями из `npm ci`. Все 815 тестов из `node --test tests/web/*.test.js` прошли. ESLint 10.13.0, HTMLHint 1.9.2 и Stylelint 17.16.0 прошли на файлах админки.
- Chromium против локального Go-сервера с временными данными. Проверены вход, запись реестра с CSRF, отказ устаревшей записи реестра с кодом 412, два запроса с истёкшей сессией и доступ к файлу галереи. Прямой запрос с закодированным переходом к файлам сборки получил 404.

Ручная проверка охватила перечисленные сценарии. Для остальных путей выполнены автоматические проверки. Настоящие многогигабайтные архивы, внешние загрузки Thunderstore, запуск FFmpeg на серверной сборке и восстановление после принудительной остановки рабочего процесса оставались за пределами локального сквозного прогона. Рабочие данные сервера не использовались.
